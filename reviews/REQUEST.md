# คำสั่งรีวิวโค้ดสำหรับ Gemini (ใช้ใน Antigravity)

ผู้ใช้จะพิมพ์ประมาณ: `ทำตาม reviews/REQUEST.md ก้อน 3` หรือ `ทำตาม reviews/REQUEST.md ก้อนถัดไป`
ถ้าไม่บอกก้อน = ทำก้อนถัดไปจาก `reviews/PROGRESS.md` ในโฟลเดอร์รีวิว (ข้อ 2)

## 1. ก่อนเริ่ม
- อ่าน `PROJECT.md` (สถานะ · กฎ · สิ่งที่ผู้ใช้ชอบ) ให้รู้ว่าอะไรตั้งใจทำแบบนั้น จะได้ไม่รายงานผิด
- แอป: หน้าเว็บ `index.html` ไฟล์เดียว (GitHub Pages) + หลังบ้าน `gas/*.gs` (Google Apps Script) + Google Sheets
- ผู้ใช้เป็นเจ้าของไร่อ้อย ใช้ iPhone มือเดียว (iOS 26 เปิดจากหน้าจอโฮม) ภาษาไทย
- **ห้ามแก้โค้ดในแอป ห้าม commit/push ขึ้น main** งานนี้คือรีวิวอย่างเดียว

## 2. ที่เก็บผล (branch `gemini-reviews` แยกจากแอป)
ครั้งแรกในเครื่อง (รันในโฟลเดอร์ rai-oy):
```
git fetch origin gemini-reviews
git worktree add ../rai-oy-reviews gemini-reviews
```
ครั้งต่อไป: `git -C ../rai-oy-reviews pull`
- เขียนผลที่ `../rai-oy-reviews/reviews/<ปีเดือนวัน YYMMDD>-g<เลขก้อน>-<ชื่อสั้นอังกฤษ>.md` เช่น `261125-g08-chat.md`
- อัปเดต `../rai-oy-reviews/reviews/PROGRESS.md` (ตาราง: ก้อน | วันที่ | ไฟล์ผล | จำนวนข้อ 🔴/🟠/🟡)
- แล้ว `git -C ../rai-oy-reviews add -A`, `commit -m "Gemini review ก้อน N"`, `push origin gemini-reviews`
- บอกผู้ใช้สั้น ๆ ว่าเสร็จก้อนไหน กี่ข้อ (ไม่ต้องวางรีวิวทั้งหมดในแชต — Claude จะไปอ่านจากไฟล์เอง)

## 4. รีวิวอะไร (ละเอียดทุกฟังก์ชันในก้อน)
- บั๊กจริง: ข้อมูลผิด/หาย/ลงซ้ำ, สต็อกไม่ตรง, error ที่ทำให้หน้าว่าง, race (กดซ้ำ, เน็ตหลุด, สลับแอประหว่างส่ง)
- ฝั่ง GAS: lock, ส่งซ้ำแล้วเบิ้ล (ทุกคำสั่งต้องส่งซ้ำได้ไม่เบิ้ล), timeout 6 นาที, โควตา, ข้อมูลว่าง/แถวหาย
- iPhone: กฎ iOS 26 ใน PROJECT.md, ปุ่มเล็กกว่า 44px, คีย์บอร์ดบัง, ช่องพิมพ์ < 16px, scrollIntoView ใน modal, หน้าต่างเด้ง (ผู้ใช้ไม่ชอบ)
- ความปลอดภัย: รหัส/ข้อมูลส่วนตัวหลุดลง log หรือ URL, innerHTML ที่ไม่ escape ข้อความจากชีต/AI
- ข้อความที่ผู้ใช้เห็น: ขัดกันเอง, ตัวเลขไม่ตรงกันสองที่, ภาษาเข้าใจยาก
